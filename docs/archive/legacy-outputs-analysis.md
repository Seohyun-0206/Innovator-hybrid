## 파일 의미

이 프로젝트는 MMLU 평가 결과를 세 가지 형식으로 남긴다.

| 파일 형식 | 의미 |
|---|---|
| `*.jsonl` | 문항 단위 실행 로그 |
| `*_metrics.json` | 집계 지표와 최종 점수 |
| `*_report.md` | 사람이 읽기 쉬운 요약 리포트 |

각 `jsonl` 레코드는 대체로 아래 필드를 가진다.

- `subject`, `category`: 과목과 상위 카테고리
- `question`, `choices`, `correct_answer`: 평가 문항 정보
- `model_output`, `parsed_answer`, `correct`: 모델 응답과 파싱/정오 여부
- `api_error`: 호출 실패 메시지
- `latency`, `input_tokens`, `output_tokens`, `cost`: 실행 비용성 지표

## 중요한 구조적 특징

- `jsonl` 파일명 시각은 실행 시작 시점에 가깝다.
- `metrics.json` 과 `report.md` 파일명 시각은 집계 시점에 가깝다.
- 따라서 같은 실행이어도 파일명 타임스탬프가 정확히 일치하지 않는다.
- 이 동작은 legacy CLI logger/reporter 구조 구조와 일치한다.

## `outputs_ollama_3` 분석

### 1. 결과 성격

- `llama3:latest`는 48문항을 끝까지 처리했다.
- API 실패와 파싱 실패가 모두 0건이다.
- 모델 출력은 매우 짧고 대부분 한 글자 또는 매우 짧은 문자열이다.
- 출력 토큰 총량이 345로 매우 작다.

### 2. 성능 해석

- 정확도는 33.3%로 낮다.
- 반면 평균 지연시간 0.79초, p95 1.44초로 매우 빠르다.
- 출력 토큰이 적어 효율 점수는 94.61로 높다.
- 안정성 점수는 100점이다.
- 최종 총점 72.99는 낮은 정확도를 높은 효율성과 안정성이 일부 보완한 결과다.

### 3. 로그에서 보이는 패턴

- 첫 문항에서 `model_output`이 `"Here are the answers:\n\nA. D\nB. D\nC. A"`처럼 지시문을 벗어난 경우가 있다.
- 답 파서는 첫 번째 A/B/C/D를 우선 추출하므로 이런 출력은 쉽게 오답으로 연결된다.
- 관련 파싱 로직은 legacy CLI metrics parser에 있다.

## `outputs_qwen3_5` 분석

### 1. `qwen3.5:9b`

- 48문항 로그와 집계 파일이 모두 존재한다.
- 정확도는 92.9%로 매우 높다.
- 카테고리 정확도도 `Humanities 100%`, 나머지 세 카테고리도 약 89~91% 수준이다.
- 그러나 API 실패가 6건 있으며, 실패한 문항은 대부분 `read timeout=120`이다.
- 평균 지연시간이 64.10초, p95가 120.00초로 매우 느리다.
- 총 출력 토큰이 60,530으로 매우 많다.

### 2. 성능 해석

- 성능 점수 91.25는 매우 높다.
- 하지만 평균 지연시간이 30초 기준을 크게 초과해 효율 점수가 43.53까지 내려간다.
- 안정성 점수도 API 실패율 12.5% 때문에 87.5로 감소한다.
- 결과적으로 총점은 78.57이며, `llama3:latest`보다 높지만 큰 차이는 아니다.

### 3. 로그에서 보이는 패턴

- 성공한 문항은 대부분 정답이며 출력 토큰도 수백~수천 단위다.
- 즉, 짧은 답만 반환하기보다 긴 추론성 응답을 생성하는 경향이 강하다.
- 긴 응답은 정확도에는 유리했지만, 지연시간과 타임아웃 위험을 크게 키운 것으로 보인다.

### 4. `qwen3.5:27b`

- 현재 `jsonl` 6개만 있고 `metrics.json`, `report.md`가 없다.
- 6개 중 5개가 `read timeout=120` 실패다.
- 실제로 성공한 문항은 `world_religions` 1건뿐이다.
- 이 상태는 평가가 조기 중단되었거나 끝까지 집계되지 못했음을 시사한다.

## 두 디렉터리의 핵심 차이

### 1. 정확도 대 효율

- `outputs_ollama_3`는 낮은 정확도 대신 빠른 응답과 안정성이 강점이다.
- `outputs_qwen3_5`의 `qwen3.5:9b`는 높은 정확도 대신 응답 시간이 길고 타임아웃이 발생한다.

### 2. 출력 스타일

- `llama3:latest`는 매우 짧게 응답한다.
- `qwen3.5:9b`는 장문 출력 경향이 강하다.
- 동일 평가 프롬프트에서도 모델별 응답 스타일 차이가 토큰/지연시간 격차로 직접 이어진다.

### 3. 운영 관점

- 실시간성이나 대량 배치 기준이면 `llama3:latest`가 더 운영 친화적이다.
- 정답률이 우선이면 `qwen3.5:9b`가 훨씬 우수하다.
- 다만 `qwen3.5:9b`와 `qwen3.5:27b`는 현재 설정에서 타임아웃 완화 없이는 운영 리스크가 크다.

## 점수 체계 관점에서 왜 총점 차이가 크지 않은가

점수 산식은 legacy CLI score calculation 기준으로 계산된다.

- `Performance = 0.7 * accuracy + 0.3 * stability`
- `Efficiency = latency + cost + token 사용량 기반`
- `Capability = stability`
- `Total = 55% performance + 25% efficiency + 20% capability`

이 때문에:

- `llama3:latest`는 정확도는 낮지만 안정성과 효율이 높아 총점이 방어된다.
- `qwen3.5:9b`는 정확도는 압도적이지만 느린 속도와 API 실패로 총점 상승 폭이 제한된다.

- 현재 산출물 기준 최고 안정성과 최고 속도 모델은 `llama3:latest`다.
- `qwen3.5:27b` 결과는 불완전하므로 정식 비교 대상로 보기 어렵다.
